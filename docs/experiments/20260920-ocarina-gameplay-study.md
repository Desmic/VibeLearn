## What this changes in our design decisions

The following are our proposed applications, not Nintendo claims or a universal
recipe for a great game.

### Capabilities should change how the player reads the world

Author a sequence of acquisition, understandable first use, then a changed-context
application. In VibeLearn, a new concept should enable a decision that the player
could not previously make reliably. Retest with a different clue or situation,
without copying the instruction. Do not add combat or equipment merely to imitate
the reference. Keep the concept's authoritative learning evidence separate from
receiving a fictional tool.

### Tutorial grammar should remain useful outside the tutorial

Our separate tutorial is still required. Its inspect/choose/act/recover grammar
must carry into the first mission with consistent visual and control cues. Audit
each taught action against later use; a tutorial-only button is a design smell.
An unsuccessful attempt should offer readable recovery and useful feedback rather
than unnecessary restart friction. Exact difficulty depends on audience and goal.

### Build spatial understanding, with assistance available

Fix the route boards so approaching and inspecting the world supplies evidence.
Keep accessible text alternatives and optional orientation help. A useful experiment
is to ask the reviewer to point out the destination, approach it, turn away, and
recover orientation. Check the protagonist and destination from alternate views.
This directly addresses the observed doorway-post occlusion and hidden route clues.
Do not treat removing all UI as the definition of good environmental design.

### A relationship needs a playable context; dialogue can deepen it

Recompose the opening shared activity so position, objects and response establish
who is involved. Dialogue can then add personality and specifics. The earlier
caption-blind test is a diagnostic of what visuals communicate, not a requirement
that all character identity or story detail be communicated without words.
A readable scene with no shared purpose still does not establish attachment.

### Include a reason to linger and a rhythm of relief

Within our bounded opening/chapter, reserve a small opportunity to inspect something,
interact or notice an optional detail without advancing the main instruction.
Judge whether that reveals character, place or a useful clue. Do not create a new
minigame subsystem to satisfy this principle. The critic should distinguish welcome
breathing room from dead time and meaningless collectible work.

### Make world changes matter to decisions

For the current proof, use existing restored/broken or open/closed states to expose
a visible consequence and alter what can be done next. A day/night simulation is
not required. Store meaningful state in the existing rules/world boundary and
preserve saves and learning IDs. Decorative palette changes alone do not prove
reactivity; the reviewer should name the before, action, after and gameplay effect.

## Execution boundary

Apply this to the existing opening repair first, then the retained tutorial and
Level 1 issues. Use the current world/story/rules specifications and reusable runtime
components. No new schemas, critic agents, broad simulation or engine rewrite are
justified by this research alone. Existing gates should evaluate the concrete
playable evidence. This documentation correction does not improve the rendered game
by itself; there is no new readiness claim. Motion/audio review remains parked.
