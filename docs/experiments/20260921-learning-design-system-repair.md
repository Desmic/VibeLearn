# Learning design and attention: system repair

21 September 2026. User reports the game is convoluted and asks to repair the
system before the game. Their completion screenshot shows critical guidance at
top left, actions/model text in a detached bottom panel and the consequence in
the world. This is a confirmed product-direction failure, not a styling request.

## Changes

Added a game-independent learning/attention contract and structural validator,
reviewed-design prototype gate, and design-alignment release gate. Build validates
structure; prototype approval is separate. Promotion uses the design stored in the
exact candidate. Missing design, stale review, needs_revision and missing native
alignment block normal preview overrides. The deployed candidate is now recorded
as user-rejected. No game runtime, save, database or deployment was changed here.

Research decisions must map to encounters and verification probes, with cost,
exclusions and art/world ownership. Critical goal/action/feedback surfaces must
belong to the focal interaction, with explicit presentation and accessibility.
This permits world-anchored semantic HTML and object inspection, not only 3D text.

Critic questions now examine teaching order, shortcuts and actual attention paths.
Native result ingestion now retains receipt v2 and exact execution requirements;
design digest binding applies only to the later intent-comparison assignment.

## Independent audit

Fresh subagent /root/learning_design_audit reviewed source and proposed design,
without inheriting this conversation. It did not play the runtime. It rejected the
draft progression pending concrete worked examples, misconception choices and
step-specific entry/opening/device presentation. That verdict remains needs_revision.

It also reproduced false-pass paths in the first gate implementation: arbitrary
hashed files could claim native play; matching anchor names could disguise detached
surfaces; checkpoint aliases could reuse one click for an entire sequence. Repairs
validate existing native assignments, sealed capsules, execution receipts and critic
results; require exact design source plus cold observations; require distinct,
ordered action-relative before/after screenshots for each step. Regression fixtures
recreate these failures. These checks operate within the trusted harness boundary;
they do not prove learning, honest observation or novice comprehension by themselves.

## Validation and boundary

A materially different paint-mixing ratio fixture exercises the same contract.
Tests reject missing practice, unknown prerequisites, detached critical presentation,
missing art/world application, stale/self-authored approval, arbitrary native proof,
reused captures, changed artifacts and missing release design. Optional system menus
and accessible alternatives remain permitted. Native ingestion has a CLI round-trip
regression; design binding does not contaminate the cold assignment.

The application suite passed 383 tests with seven skips before the final binding
and evidence-source tightening; all 41 focused affected checks passed after those changes.
Build passed, with design quality/runtime explicitly unassessed. The actual draft
prototype gate fails with needs_revision, as intended. No new GUI quality claim is
made: this turn changes authoring/review enforcement, not rendered behavior.
