The unchanged built site returned HTTP 200 at **http://127.0.0.1:8060/**, served by owned loopback Node process PID **46816** for root's native observation. Root started the ride and completed a dismount, then closed its tab. I stopped PID 46816 afterward and verified port 8060 no longer listening. No active game file was changed.

**One bounded accelerated desktop sample.** The upstream [`scripts/perf.mjs`](https://github.com/StarKnightt/summer-cycle/blob/8b977baad061e797c2f6c19cfcf07c1e79b23a67/scripts/perf.mjs) could not launch its expected Playwright Chromium revision, which was not installed locally. Instead, the [local measurement harness](../../artifacts/reference-baselines/summer-cycle/local-measure.mjs) used installed Chrome 153 through Playwright with the upstream autoplay/profiler/MSAA-4 query at **1920×1080**, after the warm-up/ready state. This changes the browser adapter, not the game source. Its browser closed cleanly after one eight-second sample. These are actual renderer/timer observations on this machine, not a comparable reproduction of the author's RTX 4060 figures, nor a phone benchmark. The FPS sequence covers only eight seconds of autoplay at one time of day; rAF intervals include scheduling variability. GPU timer extension was available, but **process CPU utilization and GPU utilization were not measured**. The profiler's JavaScript section times (e.g. frame total 10.486 ms average) are not CPU utilization; draw/triangle counters are workload, not GPU occupancy. No conclusion about phone hardware, sustained thermals, user input, audio quality, or VibeLearn performance follows.
