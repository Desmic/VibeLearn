# System and complete Level 1 readiness

User direction: continue until the reusable system and the complete journey before
and through Level 1 are ready. This is the active scope; historical candidate
headers do not freeze implementation of evidence-backed repairs.

## Gates, in order

1. **System proof:** a real incomplete native task produces a bounded repair;
   a fresh supervised GUI replay supplies actual captures; a separate context-limited
   reviewer inspects them; the existing return validator accepts only that evidence.
   Record supervision/provenance limits. No live Terminal PM/provider dispatch.
2. **Technical readiness:** build, full application tests, every active browser
   group. Reproduce failures before changing runtime or tests. Preserve saves.
3. **Whole player journey:** fresh entry, loading, prologue, separate tutorial,
   Level 1, mistake/recovery, transfer, ending, save/resume. Actual native GUI play
   is required alongside deterministic evidence.
4. **Independent criticism:** cold first-touch observations precede design intent;
   separate story, art/world, gameplay/progression and learning judgments. Astra
   reviews all lanes in one fresh context; art/world direction is mandatory. Assess motion,
   audio and accessibility using their required modalities. Unknown remains unknown.
5. **Candidate handoff:** freeze the exact resulting candidate and bind evidence,
   complete schema-v2 readiness checks, then present the complete journey to the
   user for final review. No Level 2 or deployment promotion before that checkpoint.
